# ULTrack
Разработка веб-приложения УлТрек

### 1. Клонируйте репозиторий
Каждый делает `git clone <url>` к себе на компьютер — так у всех есть полная история.

### 2. Настройте git (один раз)
`git config --global user.name "Имя"` и `git config --global user.email "email"` — чтобы коммиты были подписаны правильно.

### 3. Работайте в отдельных ветках
Перед новой задачей: `git checkout -b feature-имя`. Не пушить напрямую в `main` — меньше конфликтов.

### 4. Синхронизируйтесь перед работой
Каждый день начинай с `git pull origin main`, чтобы получить свежие изменения друзей.

### 5. Пушьте и создавайте Pull Request
`git push origin feature-имя` → на GitHub нажми **Compare & pull request** → друг проверяет → **Merge**.

### 6. Договоритесь об именах коммитов
Например: `feat: добавил авторизацию`, `fix: исправил баг с кнопкой` — так история читаема.

## Карта-прототип

В папке `applist` находится учебная карта Leaflet для Ульяновска: главная страница отображает тестовые точки, которые приходят из Django по `GET /api/demo/vehicles/` в JSON. Это **не** передача GPS водителей. Запуск и объяснение связей между HTML, CSS, JavaScript, URL и Python описаны в [`README-первые-шаги.md`](README-первые-шаги.md) и [`Первые шаги Git HTTP JSON и карта.md`](Первые%20шаги%20Git%20HTTP%20JSON%20и%20карта.md).

Эта папка подключена к истории исходного репозитория: активная ветка — `feature-Maksim`, удалённый репозиторий — `origin`. Изменения подготовлены к локальному коммиту; push на сервер не выполняется. Исходную папку `C:\Учёба\Проект\ULTrack` не редактируйте из этой копии. Бесплатные условия Яндекс.Карт не разрешают систему слежения за транспортом в реальном времени; проверяйте лицензию карт до production.
